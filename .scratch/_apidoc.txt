2.2 鉴权校验顺序
网关按以下顺序校验，任一失败立即返回对应 head.errorCode（不执行查询、不计费）：
1. appKey 是否存在 → 否则 505001（errorMsg：appId 异常）
2. appKey 是否匹配到账户 → 否则 505004（账户信息不存在）
3. 账户是否有效（启用且在有效期内）→ 否则 505007（服务尚未开通）
4. 签名是否正确 → 否则 505002（账号信息异常）
签名通过之后，主查询还会校验业务参数（非法则 505062，见 3.1.1），以及本次 dataType 是否落在账户已开通
的发票 / 税务范围内（见「开通范围」）。开通范围不符时同样返回 505007，但 errorMsg 会写明当前只开通了哪
一项；此时不执行查询、不计费、不返回 body。账户停用或过期时的 errorMsg 仅为「服务尚未开通」，与开通范
围不符的文案不同。
2.3 加签方式
1. 取出 body 中所有非空的业务参数（不含文件/字节流类型，不含值为空的参数）。
2. 按参数名（key）的 ASCII 升序排序；首字符相同则依次比较后续字符。
3. 将排序后的参数按 参数名参数值 直接拼接，最后追加 appSecret，得到待签名串。
4. 对待签名串做 MD5，取 32 位小写十六进制字符串，赋值给 sign。
示例一：body = { "creditCode": "92500233MA60R5KW8M" }，appSecret = "< 你的密钥 >"。待签名串为：
creditCode92500233MA60R5KW8M< 你的密钥 >
示例二（携带 scope）：body = { "creditCode": "92500233MA60R5KW8M", "scope": "basic" }。creditCode 的
ASCII 序在 scope 之前，待签名串为：
creditCode92500233MA60R5KW8Mscopebasic< 你的密钥 >
示例三（只开通税务、必须显式携带 dataType）：body = { "creditCode": "92500233MA60R5KW8M",
"dataType": "tax" }。creditCode 的 ASCII 序在 dataType 之前，待签名串为：
creditCode92500233MA60R5KW8MdataTypetax< 你的密钥 >
若同时携带 dataType 与 scope，ASCII 序为 creditCode、dataType、scope。
sign = MD5( 待签名串 ) 的小写十六进制值。
提示：拼接顺序由 key 的 ASCII 决定，请勿写死字段顺序；新增字段时排序会自动变化。dataType、scope 只要
出现在 body 里且非空，就必须参与签名。

static String sign(Map<String, String> body, String appSecret) throws Exception {
    List<String> keys = new ArrayList<>();
    for (Map.Entry<String, String> e : body.entrySet()) {
        if (e.getValue() != null && !e.getValue().isEmpty()) keys.add(e.getKey());
    }
    Collections.sort(keys); // ASCII 升序
    StringBuilder sb = new StringBuilder();
    for (String k : keys) sb.append(k).append(body.get(k));
    sb.append(appSecret);
    MessageDigest md = MessageDigest.getInstance("MD5");
    byte[] digest = md.digest(sb.toString().getBytes(StandardCharsets.UTF_8));
    StringBuilder hex = new StringBuilder();
    for (byte b : digest) hex.append(String.format("%02x", b));
    return hex.toString();
}
Python
import hashlib
def sign(body_params: dict, app_secret: str) -> str:
    parts = []
    for k in sorted(body_params.keys()):            # ASCII 升序
        v = body_params[k]
        if v is None or v == "":
            continue                                # 剔除空值
        parts.append(f"{k}{v}")
    raw = "".join(parts) + app_secret
    return hashlib.md5(raw.encode("utf-8")).hexdigest()  # 小写 hex

func sign(body map[string]string, appSecret string) string {
    keys := make([]string, 0, len(body))
    for k, v := range body {
        if v != "" { // 剔除空值
            keys = append(keys, k)
        }
    }
    sort.Strings(keys) // ASCII 升序
    var sb strings.Builder
    for _, k := range keys {
        sb.WriteString(k)
        sb.WriteString(body[k])
    }
    sb.WriteString(appSecret)
    sum := md5.Sum([]byte(sb.String()))
    return hex.EncodeToString(sum[:]) // 小写 hex
}

3.1.5 result.range 结构说明（返回值契约）
result.range 是一个 JSON 字符串。调用方应先对该字符串做一次 JSON.parse / 反序列化，得到含以下固定键的
对象：
顶层键
数据内容
发票数据聚合
发票维度业务段：纳税人基本信息对象 + 五类发票相关列表（字段见下）
税务数据聚合
税务维度业务段：纳税人基本信息对象 + 四类申报/征收列表（字段见下）
dataScope
本次实际查得维度：{"发票": bool, "税务": bool}
形状约定：
nsrjbxx：对象（无数据时为 {} 或字段均为空串）。
各 *List：数组（无数据时为 []）。
所有叶子字段的值统一为字符串；契约内定义但本次未返回的字段输出空串 ""（字段恒存在）。
契约之外的内容一律不返回。
业务数据已按契约字段整理为统一结构；列表内可能含不同统计口径的行（如含税/不含税、剔废等），请按业务需
要选用，勿无差别跨行直接加总。
只请求或只查得一个维度时，另一个业务段仍会出现，但其列表为空、nsrjbxx 为空对象，dataScope 中对应布尔
值为 false。请以 dataScope 判断本次实得，不要把空段当成查得。
解析示例（JavaScript）
const range = JSON.parse(resp.body.result.range);
// 1. 先看本次实得维度
console.log("实得维度", range.dataScope);
// 2. 按段取纳税人基本信息（对象）
const inv = range["发票数据聚合"];
const jb = inv.nsrjbxx || {};
console.log("企业名称:", jb.nsrmc);
// 3. 列表为数组
for (const row of inv.kphzxxList || []) {
  console.log(row.ssyf, row.kpje);
}
建议调用方按「存在即解析、空串即缺失」的方式做容错处理；契约结构固定，不会出现契约之外的字段。

五、计费说明

2. 收费档位按本次实际产生应收的类目确定，与请求了什么无关。实得发票与税务、且两类目都不在免费期
内，按「税务发票」档；只对应收发票，按「发票」档；只对应收税务，按「税务」档。请求了两项但只查
得发票，按「发票」档。
3. 主体年度免费期：同一账户 + 同一企业统一社会信用代码 + 同一类目（发票 / 税务），首次查得计费一次并
开启约一年的免费窗口；窗口内该类目再次查得不再计入应收。发票与税务窗口相互独立。因此两类目都查

六、使用手册
6.1 接入流程
1. 向商务申请账户，获取 appKey、appSecret、正式/测试域名，并确认该账户开通的是发票、税务，还是两
者（票税）。
2. 按第二章实现加签，用测试账户联调主查询与 quota / coverage。只开通一项时，主查询必须显式传入对应
的 dataType。
3. 解析 result.range：二次 JSON 解析 → 读 dataScope → 取对应业务段字段。
4. 切正式环境前完成自检清单（6.4）。
6.2 幂等与重试
建议客户端为每次业务查询生成稳定的业务流水并做好超时重试；重复提交不会导致重复计费。
读超时建议 ≥ 10 秒；超时后可用 head.logId 联系我方核对是否已落账。
网关级错误（鉴权/参数/开通范围）修正后重试即可；999 表示确定查无，无需立即重试同一主体。
